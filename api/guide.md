# Радиодетали — инструкция для ИИ-агентов

Учёт радиодеталей одного человека (владельца): что есть, сколько и где
лежит. Через API можно проверить наличие, добавить купленное, списать
израсходованное. Тексты в данных — по-русски.

## Доступ

- Адрес API: `{{BASE}}` — корень перечисляет все разделы, включая эту
  инструкцию (`guide`) и схему (`schema`).
- Каждый запрос — с заголовком `Authorization: Token <токен>`. Токен даёт
  владелец; по логину и паролю его выдаёт `POST {{BASE}}token/`
  (`username`, `password`).
- Полная схема OpenAPI 3 с описанием каждого поля:
  `GET {{BASE}}schema/?format=json` (без параметра — YAML).
- Тела запросов — JSON (`Content-Type: application/json`), кроме загрузки
  фото (multipart/form-data).

## Данные

**Деталь** (`{{BASE}}parts/`). Главное:

- `name` — название. Полупроводники, микросхемы, модули — артикулом
  («IRL520NPBF», «GY-291»); пассивные — тип, номинал, мощность или
  напряжение («Резистор 10 кОм 0.25 Вт», «Конденсатор 100 мкФ 35 В»).
- `value` — номинал или главные параметры свободным текстом («1 кОм»,
  «0.1 мкФ, 50 В», «N, 100 В, 10 А»); `package` — корпус («TO-220»,
  «SOT-23», «0603»); `mounting` — `tht` (выводной), `smd` или пусто.
- `quantity` + `unit` — сколько есть сейчас: целое число не меньше 0, `pcs`
  (штуки) или `m` (метры — провод, термоусадка).
- `category` — ID категории; `category_name` — «Верхняя / Подкатегория».
- `location` — ID места хранения; `null` — место не указано, деталь ещё
  не разобрана.
- `photo`, `datasheet_url`, `product_url`, `notes`, `description` —
  фото, даташит, товар у продавца, заметки, описание.

**Категории** (`{{BASE}}categories/`) — дерево в два уровня: верхняя
(«Диоды», `parent: null`) и подкатегории («Шоттки», `parent` — ID верхней).
Список отдаётся целиком, без страниц; `parts_count` — деталей в категории
вместе с подкатегориями.

**Места хранения** (`{{BASE}}locations/`) — плоский список («Органайзер 1 /
A3»), без страниц.

## Типовые задачи

**Есть ли деталь и сколько.** `GET {{BASE}}parts/?q=<слова>`. Каждое слово
ищется подстрокой в текстовых полях детали (название, номинал, корпус,
производитель, артикул, описание, заметки), регистр не важен, все слова
должны найтись: `q=IRL520`, `q=10 кОм`, `q=SOT-23 MOSFET`. Дробные
номиналы в данных — через точку: `q=4.7 кОм` (не «4,7»). Название
категории поиск не смотрит — для этого фильтр `category`. Смотрите
`quantity` и `unit`; `quantity: 0` — деталь заведена, но кончилась.
`count: 0` — такой детали нет; сначала попробуйте короче (часть артикула,
только номинал).

**Подобрать замену.** Числовых фильтров (напряжение, ток, ёмкость) нет:
возьмите кандидатов по категории (верхняя включает подкатегории) и
наличию — `GET {{BASE}}parts/?category=<ID>&in_stock=true`, при
необходимости `&mounting=tht` — и сравните параметры по тексту `value`.
ID категорий — из `GET {{BASE}}categories/`.

**Списать или прибавить.** `POST {{BASE}}parts/<id>/adjust/` с
`{"delta": -2}` (списать) или `{"delta": 10}` (прибавить). В ответе —
деталь с новым количеством. Ниже нуля оно не опускается, и ошибки при
этом нет: если списали больше, чем было, станет 0 — сверьте `quantity` до
и после и скажите владельцу, что не хватило. Не делайте приращения через
PATCH `quantity`: так можно затереть параллельное изменение. PATCH
`{"quantity": N}` — только чтобы записать точное число после пересчёта.

**Добавить купленное.** Сначала найдите, нет ли детали уже (по артикулу,
потом по номиналу и корпусу). Есть — `adjust` с положительным `delta`.
Нет — `POST {{BASE}}parts/` с `name`, `category` и тем, что известно
(`value`, `package`, `mounting`, `manufacturer`, `part_number`, `quantity`,
`unit`, `product_url`, `datasheet_url`); место не указывайте, если
владелец его не назвал. Оформление — как у соседей: посмотрите одну-две
детали той же подкатегории (`?category=<ID>`) и повторите их формат
`name`, `value`, `package`, `mounting`. Например, выводной резистор:
`name` «Резистор 4.7 кОм 0.25 Вт», `value` «4.7 кОм», `package`
«Аксиальный», `mounting` `tht`. `mounting` — пустая строка для модулей,
провода и расходников.

**Что ещё не разобрано.** `GET {{BASE}}parts/?location=none` — сюда входят
и детали с `quantity: 0`; только то, что физически есть, —
`&in_stock=true`.

**Фото.** `PATCH {{BASE}}parts/<id>/` multipart-полем `photo`; JSON
`{"photo": null}` — убрать фото.

## Правила

- Ничего не удаляйте (детали, категории, места) без прямой просьбы
  владельца.
- Новую категорию заводите, только если ни одна существующая не подходит;
  глубина — не больше двух уровней.
- Не создавайте дубли: одна и та же деталь — одна запись.
- Создание (`POST parts/`) и `adjust` при повторе срабатывают дважды. Если
  ответ не пришёл (таймаут, обрыв), сначала перечитайте деталь
  (`GET parts/<id>/` или поиск) и только потом повторяйте.
- Списки деталей постраничные: `count`, `next`, `previous`, `results`; по 50,
  `page_size` — до 1000. `count` — число записей (позиций), не штук; штуки
  — сумма `quantity` с учётом `unit`. Сортировка — `ordering` (`name`,
  `quantity`, `updated_at`, `created_at`; `-` — по убыванию).

## Ошибки

- `400` — неверные данные; в теле — поля и тексты ошибок, например
  `{"quantity": ["…"]}` или `{"parent": ["…"]}`.
- `401` / `403` — нет токена или он неверный.
- `404` — нет такой записи.
- `409` — нельзя удалить категорию, в которой есть детали или подкатегории.

## Пример

```bash
curl -H 'Authorization: Token <токен>' '{{BASE}}parts/?q=1N4007'

curl -X POST -H 'Authorization: Token <токен>' \
     -H 'Content-Type: application/json' \
     -d '{"delta": -1}' '{{BASE}}parts/42/adjust/'
```
